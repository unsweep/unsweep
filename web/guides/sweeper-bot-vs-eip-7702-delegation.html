Sweeper bot vs malicious EIP-7702 delegation

UNSWEEP will never DM you first or ask for your seed phrase or private key. This page is informational; nothing on it is a guarantee of success.

Both can drain a compromised wallet, but they work differently.

Sweeper bot (off-chain)

A script run by an attacker who holds the private key. It watches the address and signs transfers when funds arrive. The account itself is unchanged on-chain: it still has no code.

Malicious EIP-7702 delegation (on-chain)

With EIP-7702 an EOA can delegate to contract code; the account code becomes the delegation indicator 0xef0100 followed by the target address. If an attacker obtained a signed authorization, that code can run on the wallet, for example to forward incoming funds.

How to tell them apart

  • Read the account code (eth_getCode). 0x means no delegation; a value starting with 0xef0100 means the wallet is delegated, and the next 20 bytes are the target.
  • Outgoing transfers signed by your address right after deposits suggest a bot holding the key.
  • Both can be present at the same time.

Why it matters

An EIP-7702 rescue sets a new delegation inside the same atomic transaction, replacing the previous one. The attacker still holds the key and could re-delegate later, so a rescued wallet should not be reused. See malicious EIP-7702 delegation.

Scope: Base: 16 verified tokens. Arbitrum: 12 verified tokens. Other ERC-20 tokens may be detected, without guarantee. Ethereum: read-only diagnostic only (no rescue). Funds already taken cannot be recovered and NFTs are not rescued.

FAQ

What is the difference between a sweeper bot and a malicious delegation?

A sweeper bot is an off-chain script that uses the stolen key; a malicious EIP-7702 delegation is on-chain code set on the account itself.

How do I know if my wallet is delegated?

Read the account code with eth_getCode: 0x means no delegation; code starting with 0xef0100 is an EIP-7702 delegation indicator followed by the target address.

Can both happen at once?

Yes. An attacker with the key can run a bot and also set a delegation.

Can I keep using the wallet after a rescue?

It is not recommended: the attacker still holds the key. Move to a new wallet.
