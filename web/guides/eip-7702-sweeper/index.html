EIP-7702 sweeper delegation: what it is and how to check for one

This guide is informational. Funds already moved out of a wallet usually cannot be recovered. We never ask for any key in chat, email or DM and we never write first. The only key a rescue uses is the one of the already-compromised wallet, typed by you on unsweep.com and used only inside your browser.

What EIP-7702 changes

EIP-7702 (part of the Pectra upgrade) lets a normal externally owned account (EOA) point to a smart contract. The owner signs an authorization; once it is included in a transaction, the account's code becomes the 23-byte marker 0xef0100 followed by the 20-byte address of the delegate contract. From then on, calls to the account run the delegate's code in the context of the account, with the account's balance and tokens.

Legitimate uses include batching several actions in one transaction or gas sponsorship. The same mechanism is dangerous if the delegate was chosen by an attacker.

How a sweeper uses it

  • An attacker who has the private key (leaked file, phishing page, malicious download) signs an authorization that delegates the account to a contract they control.
  • That contract can forward any incoming native coin or token to the attacker automatically, often in the same block in which it arrives.
  • Before EIP-7702, sweepers were off-chain bots racing to send a transfer after each deposit. With a delegation, the sweep logic can live on-chain, which makes it faster and harder to beat.
  • The delegation stays until the account signs a new authorization (for example, delegating to the zero address to clear it). Because the attacker also holds the key, they can simply re-delegate.

How to check an address (read-only)

You only need the public address. Nothing has to be signed.

  1. Call eth_getCode(address, "latest") on any node of the network.
  2. If the result is 0x, the account has no code and no delegation.
  3. If the result starts with 0xef0100 and is 23 bytes long, the account is delegated. The remaining 20 bytes are the delegate contract address.
  4. Look that delegate contract up in a block explorer. Check whether its source is verified, who deployed it and whether it was something you intentionally set up.

Example with a command line JSON-RPC request:

curl -s -X POST <RPC_URL> -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_getCode","params":["0xYOUR_ADDRESS","latest"]}'

Or use the free read-only check on this site for Base and Ethereum mainnet. It reports the delegation target, nonce, balances and open approvals.

Signs that a delegation is malicious

  • You do not remember enabling any smart account feature, but the address is delegated.
  • Deposits disappear within seconds, even small amounts sent to pay gas.
  • The delegate contract is unverified or was deployed recently by an unknown address.
  • The nonce increased with transactions you did not send.

What to do

  • Treat the private key and seed phrase as permanently exposed. Do not use that wallet for new funds.
  • Do not send gas money to the compromised address. A delegated sweeper will usually forward it immediately.
  • Create a new wallet with a fresh seed phrase on a device you trust, and move future activity there.
  • Review open token approvals: see how to find and revoke approvals.
  • Follow the compromised wallet checklist.
  • Be very careful with anyone offering recovery in private messages. Asking for your seed phrase or for an upfront payment is a common scam pattern.

Limits

Clearing or replacing a delegation requires a signature from the compromised key, and the attacker can do the same. Removing a delegation does not reverse transfers that already happened. Assets that are locked, staked or vesting in the account may sometimes be moved out in a single sponsored transaction, but there is no guarantee and timing matters.
